## ۰. روش و حدود اطمینان

- **منبع:** WebSearch در ۲۶ نوامبر ۲۰۲۶ با ۱۶ پرس‌وجوی فارسی و ترکیبی، به‌علاوهٔ باز کردن سه صفحهٔ فارسی رتبه‌دار MCP (فرادرس، کالی‌بویز، دیجی‌نامه) و دو صفحهٔ مستندات رسمی (tool use overview و MCP connector در platform.claude.com).
- ایندکس WebSearch آمریکایی است. نتایجش **تقریبی** از SERP فارسی گوگل است و autocomplete و «جست‌وجوهای مرتبط» را نشان نمی‌دهد.
- **هیچ عدد حجم جست‌وجویی نداریم و نمی‌سازیم.** امتیاز تقاضا برآورد است و بر نشانه‌های قابل‌مشاهده تکیه دارد: چند ناشر فارسی سراغ موضوع رفته‌اند، چقدر تازه (۱۴۰۵) نوشته‌اند، دورهٔ پولی فارسی برایش هست یا نه، و نسخهٔ فارسی مستندات رسمی وجود دارد یا نه. هرجا تقاضای فارسی را مستقیم ندیدیم، صریح نوشته‌ایم.
- پیش از نوشتن: autocomplete گوگل را برای کلیدواژهٔ اصلی هر بریف دستی چک کنید و جدول PAA را با آن تکمیل کنید.

### چرا این دو

1. **MCP چیست (موضوع داغ و پرتقاضا).** قوی‌ترین نشانهٔ تقاضای فارسی را در کل فهرست دارد: نُه ناشر فارسی در سه ماه اخیر درباره‌اش نوشته‌اند و یک دورهٔ پولی هم هست. رقابت متوسط است، ولی شکاف‌ها روشن‌اند: هیچ صفحهٔ فارسی کد اجرایی، مقایسه با tool use یا function calling، یا اتصال از خود Claude API (MCP connector) ندارد. فقط یکی از سه صفحه‌ای که باز کردیم prompt injection را با نام آورده است. MCP پروتکل Anthropic است، پس مستقیم در محور ماست. در تقویم هفتهٔ ۱۲ بود. **پیشنهاد: جلو بیاید**، چون پنجرهٔ تازگی‌اش محدود است و رقبا الان دارند صفحه می‌سازند.
2. **Tool use در Claude (موضوع همیشگی توسعه‌دهنده).** کم‌رقابت‌ترین موضوع فهرست است: هیچ صفحهٔ فارسی ندارد و نسخهٔ فارسی مستندات رسمی هم نیست. بیشترین تناسب با تبدیل را هم دارد، چون کسی که tool use پیاده می‌کند در حال ساختن محصول روی API است. پایهٔ مفهومی مقالهٔ MCP هم هست و دو مقاله یک جفت لینک‌دهی طبیعی می‌سازند (MCP همان ابزارها را استاندارد می‌کند). راه چت‌بات پشتیبانی، RAG و ایجنت را هم برای هفته‌های بعد باز می‌کند.

**چرا بقیه نه (فعلاً):**
- **Claude Code** ۱۱ امتیاز گرفت و نامزد بعدی است. ولی SERP فارسی‌اش را درگاه‌های فروش دسترسی گرفته‌اند و پاسخ صادقانه به «چطور شروع کنم» از اشتراک و حساب می‌گذرد که خط قرمز ماست. باید زاویهٔ «Claude Code با کلید API تیمی و کنترل هزینه» را با دقت بنویسیم.
- **چت‌بات پشتیبانی** ۱۲ امتیاز دارد، ولی خروجی خوبش به tool use (و بعداً RAG) تکیه دارد. بهتر است بعد از مقالهٔ tool use بیاید.
- **استریم، JSON، خطاها و context window** خیلی کم‌رقابت‌اند، ولی همین الان بخشی از ستون یا مقاله‌های دیگرند. بهتر است اول آن بخش‌ها را در Search Console بسنجیم و بعد تصمیم بگیریم که مقالهٔ جدا لازم است یا گسترش همان بخش.

**پیشنهاد تغییر تقویم:** هفتهٔ ۱ = Tool use + MCP. استریم و چت‌بات پشتیبانی به هفتهٔ ۲ می‌روند (چت‌بات حالا روی مقالهٔ tool use بنا می‌شود). Claude Code از هفتهٔ ۷ به هفتهٔ ۳ می‌آید.

**مرزبندی دو مقاله با هم (ضدهم‌نوع‌خواری):**
- **tool use** = «مدل چطور تابع *شما* را صدا می‌زند»: تعریف ابزار، حلقه، tool_choice، خطا، امنیت اجرا.
- **MCP** = «چطور ابزارها و داده‌ها را یک بار و استاندارد در اختیار هر برنامهٔ هوش مصنوعی بگذاریم»: پروتکل، معماری، سرور، اتصال، امنیت زنجیرهٔ تأمین.
- MCP حلقهٔ tool use را دوباره توضیح نمی‌دهد. یک پاراگراف می‌آورد و لینک می‌دهد. مقالهٔ tool use هم MCP را در یک H3 معرفی می‌کند و لینک می‌دهد.

### نیت جست‌وجو و خواننده

### زاویه‌ای که SERP فعلی را شکست می‌دهد

صفحه‌های فارسی فعلی (فرادرس، کالی‌بویز، دیجی‌نامه و بقیه) تعریف، تشبیه USB-C، Host/Client/Server و مقایسه با API و RAG را دارند. این‌ها را **ندارند**:
1. **کد اجرایی.** فرادرس و دیجی‌نامه هیچ کدی ندارند و کالی‌بویز فقط یک بلوک پیکربندی JSON دارد. ما یک سرور MCP کامل و کوچک به پایتون (SDK رسمی، دکوراتور `@mcp.tool()`) و تست آن با MCP Inspector می‌آوریم.
2. **فرق دقیق MCP با tool use یا function calling.** هیچ‌کدام صریح مقایسه نکرده‌اند. این سؤالی است که هر توسعه‌دهنده‌ای که API کار کرده می‌پرسد. ما جدول «چه کسی ابزار را تعریف می‌کند، کجا اجرا می‌شود، کی ارزش دارد» می‌دهیم.
3. **MCP از خود Claude API.** هیچ صفحهٔ فارسی MCP connector در Messages API را توضیح نداده است: پارامتر `mcp_servers`، `mcp_toolset` در `tools`، سرور راه‌دور روی HTTP و محدودیت‌ها. همه فقط از Claude Desktop یا Claude Code نام می‌برند. ما سه مسیر اتصال را جدا می‌کنیم: اپ‌های آماده (Desktop/Code)، connector در API، و کلاینت MCP خودتان.
4. **امنیت در سطح تیم.** prompt injection از طریق خروجی ابزار، سرورهای شخص ثالث به‌عنوان زنجیرهٔ تأمین، کمترین دسترسی، allowlist ابزارها و تأیید انسانی. به شکل چک‌لیست قابل‌اجرا، نه فقط هشدار کلی.
5. **تاریخ‌دار و دقیق.** کادر «آخرین بازبینی» با نسخهٔ beta header و اشاره به اینکه MCP به Agentic AI Foundation (زیر Linux Foundation) سپرده شده، با لینک به مستندات رسمی.

### کد، جدول و دیاگرام

- **دیاگرام ۱ (SVG یا ASCII در بلوک `text`):** کاربر → Host (مثلاً Claude Code یا اپ شما) → MCP Client → چند MCP Server (فایل، پایگاه داده، Jira) → داده/سیستم. پیکان JSON-RPC.
- **جدول ۱:** Tools / Resources / Prompts: چه هستند، چه کسی فعالشان می‌کند (مدل، اپ یا کاربر)، مثال.
- **جدول ۲:** MCP در برابر tool use در برابر API مستقیم در برابر RAG. ستون‌ها: چه چیزی را حل می‌کند، کجا تعریف می‌شود، کجا اجرا می‌شود، کی مناسب است.
- **کد ۱ (python):** سرور MCP با SDK رسمی پایتون (`FastMCP`)، یک ابزار فقط‌خواندنی مثل `get_order_status(order_id)` با docstring، و اجرای `mcp dev server.py` برای Inspector. پیش از انتشار دقیقاً با README رسمی `modelcontextprotocol/python-sdk` تطبیق داده شود.
- **کد ۲ (bash):** افزودن سرور به Claude Code با `claude mcp add` و بررسی با `claude mcp list` (با مستندات code.claude.com تطبیق شود).
- **کد ۳ (python):** فراخوانی Messages API با MCP connector: `client.beta.messages.create(..., mcp_servers=[{"type": "url", "url": ..., "name": ..., "authorization_token": os.environ[...]}], tools=[{"type": "mcp_toolset", "mcp_server_name": ...}], betas=[...])`. توکن از متغیر محیطی خوانده شود. نسخهٔ beta header در کادر تاریخ‌دار بیاید (در بازبینی امروز مستندات `mcp-client-2025-11-20` و `mcp-client-2026-09-15` را فهرست کرده‌اند و نسخهٔ `mcp-client-2025-04-04` منسوخ است).
- **کد ۴ (json):** یک `mcp_toolset` با `default_config: {"enabled": false}` و فقط یک ابزار فعال در `configs`، به‌عنوان الگوی allowlist.
- **کادر هشدار:** connector فعلاً فقط *tool calls* را از مشخصات MCP پشتیبانی می‌کند و سرور باید روی HTTP عمومی باشد (Streamable HTTP یا SSE). سرور محلی stdio مستقیم وصل نمی‌شود. (منبع: صفحهٔ MCP connector، platform.claude.com)
- **چک‌لیست امنیت:** ۸ تا ۱۰ مورد تیک‌دار.

### FAQ (۴ تا ۵ پرسش)

1. MCP جای API را می‌گیرد؟ (نه؛ لایه‌ای روی APIهای موجود است.)
2. MCP فقط با Claude کار می‌کند؟ (نه؛ استاندارد باز است و ابزارها و ارائه‌دهندگان دیگر هم پشتیبانی‌اش می‌کنند. ادعای مشخص دربارهٔ هر محصول فقط با منبع.)
3. برای استفاده از MCP حتماً باید سرور بسازم؟ (نه؛ سرورهای آماده هست. ولی هر سرور شخص ثالث را مثل یک وابستگی بازبینی کنید.)
4. فرق MCP با function calling چیست؟ (function calling سازوکار مدل است و MCP استاندارد عرضهٔ ابزار.)
5. آیا MCP امن است؟ (به پیاده‌سازی و دسترسی‌ها بستگی دارد: کمترین دسترسی، allowlist و تأیید انسانی.)

### هوک (ایدهٔ ۲ تا ۳ جملهٔ اول)

«اگر برای هر ابزار جدید، از Jira تا پایگاه دادهٔ سفارش‌ها، یک اتصال اختصاصی به مدل نوشته باشید، مشکلی را که MCP حل می‌کند می‌شناسید. Model Context Protocol راه استانداردی است که هر ابزار یک بار سرور می‌شود و هر برنامهٔ هوش مصنوعی یک بار کلاینت. در این مقاله می‌بینیم MCP دقیقاً چیست، چه فرقی با tool use دارد و چطور یک سرور کوچک بسازیم و آن را امن به Claude وصل کنیم.»

### زاویه‌ای که SERP فعلی را شکست می‌دهد

SERP فارسی برای این موضوع خالی است. رقیب واقعی صفحه‌های انگلیسی‌اند (IBM، Databricks، jumpcloud، dev.to) و مستندات رسمی که نسخهٔ فارسی ندارند. صفحه‌های تعریفی انگلیسی مفهوم را می‌گویند ولی کد Claude ندارند. dev.to کد دارد ولی بخش تولید (production) را ندارد. مستندات رسمی کامل است ولی پراکنده: overview، define، handle، parallel، strict و tool runner صفحه‌های جدا هستند. زاویهٔ ما:
1. **تنها مرجع فارسی و یک‌جا** برای چرخهٔ کامل: تعریف، حلقه، چند ابزار، خطا، تولید.
2. **حلقهٔ کامل و قابل اجرا** (نه فقط تعریف ابزار): `stop_reason: "tool_use"`، اجرای تابع، `tool_result` با `tool_use_id`، تکرار تا پاسخ نهایی، و سقف تعداد دور برای جلوگیری از حلقهٔ بی‌پایان.
3. **نکته‌های تولید که در صفحه‌های تعریفی نیست:** توضیح ابزار (description) چطور نوشته شود، `is_error` برای گزارش خطا به مدل، ابزارهای موازی و `disable_parallel_tool_use`، `strict: true` برای تطابق با schema، اعتبارسنجی ورودی پیش از اجرا، و تأیید انسانی برای ابزارهایی که چیزی را تغییر می‌دهند.
4. **هزینه بدون قیمت:** تعریف ابزارها، بلوک‌های tool_use و tool_result و یک system prompt خودکار همه توکن ورودی‌اند. فقط سازوکار را توضیح می‌دهیم و به مقالهٔ توکن لینک می‌دهیم. هیچ عددی نمی‌آوریم.
5. **مثال فارسی واقعی:** کاربر فارسی می‌پرسد «سفارش A-1042 کجاست؟» و پاسخ نهایی هم فارسی است، در حالی که schema و کامنت‌های کد انگلیسی می‌مانند.

## ۴. قواعد مشترک برای نویسنده (هر دو مقاله)

- **بدون قیمت و بدون وعده.** هزینه فقط به شکل سازوکار (چه چیزی توکن حساب می‌شود). عددهای سیستم‌پرامپت ابزار در مستندات هست، ولی عدد نیاوریم و به مستندات لینک بدهیم.
- **هیچ اشاره‌ای** به دسترسی از ایران، VPN، اکانت، اشتراک، تحریم، «رایگان» یا «نامحدود» نشود. در مقالهٔ MCP، بخش Claude Desktop/Code فقط *چه کاری می‌کند* را بگوید، نه *چطور حساب یا اشتراک بگیرید*.
- **کلاود ایران** حداکثر ۲ بار، فقط با لحن پیش‌عرضه و مشروط. جملهٔ «مستقل است و وابسته به Anthropic نیست» حتماً بیاید. هیچ‌وقت ننویسید «فعال است» یا «رسمی».
- **کادر تاریخ‌دار** برای نام مدل‌ها، نسخهٔ beta header ها و وضعیت beta، با لینک به platform.claude.com / docs.claude.com.
- **هر شناسهٔ API** (`mcp_servers`، `mcp_toolset`، `tool_choice`، `disable_parallel_tool_use`، `is_error`، `strict`) روز نوشتن دوباره با مستندات رسمی چک شود. این بریف بر اساس بازبینی ۲۶ نوامبر ۲۰۲۶ است.
- **ترتیب انتشار:** اول tool use، بعد MCP (یک تا سه روز فاصله)، تا لینک «پیش‌نیاز» MCP از روز اول کار کند. همان روز لینک‌های برگشتی بالا در مقاله‌های موجود اضافه شوند و `updated` آن‌ها تغییر کند.
