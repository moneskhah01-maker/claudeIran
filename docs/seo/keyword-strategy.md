# استراتژی کلیدواژه و برنامهٔ محتوای بلاگ «کلاود ایران»

> نسخهٔ ۱ · ۲۰۲۶-۱۱-۲۳ · دامنه: https://claudeiran.com (fa-IR) · وضعیت سرویس: پیش از راه‌اندازی، مشروط به تأمین تأییدشده و قرارداد · مستقل و بدون وابستگی به Anthropic

## ۰. روش کار و حدود اطمینان

- **منبع داده:** بررسی SERP با ابزار WebSearch در ۲۳ نوامبر ۲۰۲۶، با ۲۱ پرس‌وجوی فارسی و ترکیبی. این ابزار ایندکس آمریکایی است، پس نتایجش تقریبی از SERP فارسی گوگل است و با google.com از داخل ایران یکی نیست. Autocomplete و «جست‌وجوهای مرتبط» گوگل را مستقیم ندیدیم.
- **حجم جست‌وجو:** هیچ عددی نمی‌دهیم. «حجم نسبی» (زیاد/متوسط/کم) برآورد است و بر این‌ها تکیه دارد: گستردگی موضوع، اینکه ناشران و دوره‌های فارسی (مکتب‌خونه، فرادرس، دیجی‌کالا مگ، زومیت) سراغش رفته‌اند یا نه، و تعداد صفحه‌های تبلیغاتی رقبا.
- **رقابت:** بر پایهٔ چیزی است که در نتایج دیدیم: صفحهٔ فارسی هست یا نیست، عمق و تازگی‌اش، و اینکه نتایج انگلیسی‌اند یا نه. **وقتی پرس‌وجوی فارسی فقط نتیجهٔ انگلیسی می‌دهد، فرصت است.**
- **اعتبارسنجی:** ۶ تا ۸ هفته بعد از انتشار، این برآوردها را با Search Console جایگزین می‌کنیم. پیش از نوشتن هر مقاله هم autocomplete گوگل را دستی چک می‌کنیم.

## ۱. خلاصهٔ فرصت و راهبرد

**فرصت.** برای مفاهیم فنی Claude API تقریباً محتوای فارسی وجود ندارد. «Claude API چیست»، تفاوت Haiku/Sonnet/Opus، مهاجرت از OpenAI، استریم، prompt caching، tool use، context window و کنترل هزینه همه فقط نتیجهٔ انگلیسی دادند (مستندات رسمی platform.claude.com، Zapier، DataCamp، dev.to). فارسی‌ها فقط در چند جا دیده شدند:
- `help.openai.com/fa-ir`: ترجمهٔ رسمی مقاله‌های توکن و امنیت کلید، ولی فقط دربارهٔ OpenAI.
- دیجی‌کالا مگ: مقایسهٔ ChatGPT و Claude با مدل‌های قدیمی (Sonnet 3.5 و GPT-4o).
- صفحه‌های دوره در مکتب‌خونه (پرامپت‌نویسی، Claude Code، چت‌بات پشتیبانی) و فرادرس (RAG).
- صفحه‌های تبلیغاتی درگاه‌های فروش API (AvalAI، لیارا در دیجیاتو، apisrouter، qcode، صفحه‌های فارسی ssdnodes). بخش بزرگی از این‌ها روی نیت «دسترسی از ایران» کار می‌کنند و ما عمداً از آن نیت دوری می‌کنیم.

**راهبرد.** «اقتدار موضوعی» در یک محور: **«Claude API برای توسعه‌دهندگان و تیم‌ها»**. ساختار hub-and-spoke است: یک مقالهٔ ستون («Claude API چیست») و مقاله‌های اقماری که همه به آن و به هم لینک می‌دهند. دامنهٔ تازه با سرعت بیشتری روی پرس‌وجوهای کم‌رقابت و مفهومی جا می‌افتد، پس:
1. **فاز ۱ (لانچ):** ۸ مقالهٔ عمیق روی موضوع‌هایی که SERP فارسی‌شان خالی یا انگلیسی است. هدف اول رتبه است و نه حجم.
2. **فاز ۲ (ماه ۱ تا ۳):** دو مقاله در هفته روی long-tailهای فنی و کاربردی، و تقویت خوشه‌ها.
3. **فاز ۳ (بعد از دادهٔ Search Console):** رفتن سراغ پرس‌وجوهای پرحجم‌تر مثل «Claude یا ChatGPT» و «پرامپت‌نویسی»، و به‌روزرسانی هر مقاله‌ای که در جایگاه ۸ تا ۲۰ است.

**قاعدهٔ ضدهم‌نوع‌خواری.** صفحهٔ اصلی فعلاً هدف تجاری «Claude API / دسترسی به Claude API / کلید API / مدیریت هزینه» را دارد (`docs/copy-deck-v2.md`). مقاله‌های بلاگ فقط نیت **اطلاعاتی** را هدف می‌گیرند («چیست»، «چطور»، «تفاوت») و برای نیت تجاری به صفحهٔ اصلی لینک می‌دهند.

**قاعدهٔ اعتماد.** هر مقاله این‌ها را دارد: جملهٔ «کلاود ایران مستقل است و وابسته به Anthropic نیست»، تاریخ «آخرین بازبینی»، و لینک به مستندات رسمی. هیچ قیمتی در مقاله نمی‌آید. نام مدل‌ها فقط در یک کادر تاریخ‌دار نوشته می‌شود.

### کلیدواژه‌های حذف‌شده (هدف نمی‌گیریم و در عنوان، تگ، alt، anchor و URL هم نمی‌آوریم)

- خرید اکانت Claude / ChatGPT، اکانت Pro / Max / Plus، خرید اشتراک، فعال‌سازی اکانت، شارژ اشتراک
- اکانت اشتراکی / شریکی / مشترک، اکانت آماده
- VPN، فیلترشکن، پروکسی، تغییر IP یا DNS، شمارهٔ مجازی برای ثبت‌نام
- «Claude در ایران»، «استفاده از Claude در ایران»، «Claude API از ایران»، «دسترسی به Claude در ایران»، رفع تحریم، دور زدن محدودیت منطقه‌ای و هر محتوایی که دور زدن Supported Regions Policy شرکت Anthropic را آموزش دهد
- رایگان، نامحدود، «رایگان و نامحدود»، کرک، ارزان‌ترین
- بررسی یا مقایسهٔ درگاه‌هایی که بر پایهٔ دور زدن محدودیت کار می‌کنند

**رزرو برای بعد از گیت G0 (فقط صفحهٔ اصلی، نه بلاگ):** «سرویس Claude API»، «پنل Claude API»، «شارژ تومانی API» و «صورتحساب تومانی هوش مصنوعی». این‌ها نیت تجاری دارند و رقبا همین الان رویشان هستند. تا وقتی تأمین و قرارداد تأیید نشده، فقط با همان لحن مشروط صفحهٔ اصلی می‌مانند.

### ۱) ستون: Claude API چیست

- **slug:** `claude-api`
- **عنوان:** Claude API چیست؟ راهنمای کامل برای توسعه‌دهندگان و تیم‌ها
- **متا:** Claude API چیست و چطور کار می‌کند؟ از Messages API و کلید API تا مدل‌ها، توکن، استریم و کنترل هزینه؛ راهنمای فارسی برای توسعه‌دهندگان و تیم‌ها.
- **کلیدواژهٔ اصلی:** Claude API چیست · **فرعی:** API کلاد، Anthropic API، Messages API، آموزش Claude API، کلید API کلاد
- **نیت:** اطلاعاتی · **خواننده:** توسعه‌دهندهٔ بک‌اند، مدیر محصول و CTO تیم کوچک
- **ساختار:**
  - H2 Claude API در یک نگاه
    - H3 تفاوت API با اپ Claude (نرم‌افزار در برابر گفت‌وگوی انسانی)
    - H3 چه کسانی به API نیاز دارند
  - H2 Claude API چطور کار می‌کند
    - H3 چرخهٔ درخواست و پاسخ و stateless بودن
    - H3 Messages API: `model`، `max_tokens`، `system` و `messages`
    - H3 نقش‌ها (user/assistant) و نگه‌داشتن تاریخچهٔ گفت‌وگو
  - H2 مدل‌های Claude در یک پاراگراف (← مقالهٔ ۳)
  - H2 توکن، پنجرهٔ زمینه و صورتحساب (← مقالهٔ ۲)
  - H2 قابلیت‌های کلیدی
    - H3 استریم پاسخ
    - H3 Tool use
    - H3 ورودی تصویر و PDF
    - H3 Prompt caching و Batch
    - H3 سازگاری با قالب OpenAI و محدودیت‌هایش (← مقالهٔ ۶)
  - H2 اولین درخواست: curl، Python و Node.js
  - H2 کاربردهای رایج برای تیم‌ها (پشتیبانی، خلاصه‌سازی، دستیار کد، استخراج داده)
  - H2 دسترسی در تیم: کلید جدا برای هر پروژه، بودجه و سقف خروجی (← `/#features`، `/console.html`)
  - H2 خطاهای رایج: 400، 401، 429 و 529 (overloaded)
  - H2 جمع‌بندی و قدم بعدی (← `/#early-access`)
- **FAQ (اسکیما):**
  1. Claude API با اشتراک claude.ai چه فرقی دارد؟
  2. برای شروع کار با Claude API چه چیزهایی لازم است؟
  3. Claude API متن فارسی را می‌فهمد و فارسی پاسخ می‌دهد؟
  4. هزینهٔ Claude API چطور محاسبه می‌شود؟
  5. می‌شود کدی که برای OpenAI نوشته شده را به Claude وصل کرد؟
- **لینک‌های درونی:** به همهٔ مقاله‌های ۲ تا ۸ (هر کدام در بخش مربوط) و به `/#developers`، `/#how`، `/#features`، `/console.html` و `/#early-access`
- **زاویهٔ برد:** SERP فقط مستندات و آموزش‌های انگلیسی دارد. این اولین مرجع فارسی کامل و به‌روز می‌شود و یک دیاگرام چرخهٔ درخواست، نمونه‌کد سه‌زبانه و جدول خطاها دارد. بر خلاف صفحه‌های رقبا، سراغ «دسترسی» و ترفند نمی‌رود و فقط مفهوم و مهندسی را توضیح می‌دهد.

### ۲) توکن و محاسبهٔ هزینه

- **slug:** `claude-tokens-pricing`
- **عنوان:** توکن چیست؟ محاسبهٔ هزینهٔ Claude API به زبان ساده
- **متا:** توکن در مدل‌های زبانی یعنی چه، توکن ورودی و خروجی چه فرقی دارند و هزینهٔ هر درخواست Claude API چطور حساب می‌شود؟ با فرمول و مثال عملی.
- **کلیدواژهٔ اصلی:** توکن چیست · **فرعی:** محاسبهٔ هزینهٔ API، توکن ورودی و خروجی، شمارش توکن متن فارسی، max_tokens چیست، صورتحساب توکنی
- **نیت:** اطلاعاتی · **خواننده:** توسعه‌دهنده و مدیر مالی یا IT که باید بودجه برآورد کند
- **ساختار:**
  - H2 توکن به زبان ساده
    - H3 چرا تعداد توکن با تعداد کلمه برابر نیست
    - H3 متن فارسی و توکن: چرا باید خودتان بشمارید
  - H2 توکن ورودی و توکن خروجی
    - H3 چه چیزهایی ورودی حساب می‌شوند (system prompt، تاریخچه، تعریف ابزارها، تصویر)
    - H3 خروجی، `max_tokens` و `stop_reason`
    - H3 توکن‌های تفکر (thinking) هم خروجی حساب می‌شوند
  - H2 فرمول هزینهٔ یک درخواست (نمادین: ورودی × نرخ ورودی + خروجی × نرخ خروجی)
    - H3 اثر cache (نوشتن و خواندن) بر ورودی
    - H3 اثر پردازش Batch
  - H2 مثال عملی با نرخ‌های فرضی X و Y: چت‌بات پشتیبانی با ۱۰ پیام
  - H2 شمارش توکن پیش و پس از ارسال (endpoint شمارش توکن و فیلد `usage` در پاسخ)
  - H2 پنجرهٔ زمینه و رابطه‌اش با هزینه
  - H2 از توکن تا گزارش مالی: صورتحساب توکنی و کیف پول پیش‌پرداخت (← `/#features`، `/console.html`)
- **FAQ:**
  1. هر توکن تقریباً چند کلمه است؟
  2. چرا نرخ توکن خروجی معمولاً از ورودی بیشتر است؟
  3. max_tokens چیست و چه مقداری بگذاریم؟
  4. چطور پیش از ارسال درخواست، تعداد توکن را بدانیم؟
- **لینک‌های درونی:** ← ستون (۱)، کنترل هزینه (۵)، انتخاب مدل (۳)؛ `/#features`، `/console.html`، `/#faq`
- **زاویهٔ برد:** تنها صفحهٔ فارسی موجود ترجمهٔ OpenAI است و Claude و متن فارسی را پوشش نمی‌دهد. ما این‌ها را اضافه می‌کنیم: مکانیزم مخصوص Claude (cache، Batch، thinking)، روش سنجش برای متن فارسی، و یک قالب جدول برآورد هزینه که قابل دانلود است و عدد ثابت ندارد، پس کهنه نمی‌شود.

## ۵. چک‌لیست سئوی درون‌صفحه و فنی (سایت ایستای فارسی)

**عنوان و متا**
- [ ] `<title>` یکتا و حداکثر ۶۰ نویسه، با کلیدواژهٔ اصلی در ابتدا و «| کلاود ایران» فقط اگر جا شد
- [ ] متای توضیحات یکتا و حداکثر ۱۵۵ نویسه، با کلیدواژه و وعدهٔ مشخص
- [ ] `og:title`، `og:description`، `og:type=article`، `og:locale=fa_IR` و `og:image` اختصاصی برای هر مقاله (`tools/assets.mjs` را می‌شود برای هر مقاله اجرا کرد)

**سرتیترها و متن**
- [ ] یک H1 در هر صفحه (همان عنوان یا نسخهٔ کمی بلندترش) و سلسله‌مراتب H2 و H3 بدون پرش
- [ ] `<html lang="fa" dir="rtl">`، «ی» و «ک» فارسی (بدون نویسهٔ عربی) و نیم‌فاصلهٔ درست
- [ ] اصطلاحات فنی یک‌بار با معادل فارسی و یک‌بار به انگلیسی (مثلاً «پنجرهٔ زمینه (context window)»)
- [ ] نمونه‌کد داخل `<pre dir="ltr">` با رنگ‌آمیزی در زمان build (بدون JS سمت کاربر)
- [ ] پاراگراف اول در ۲ تا ۳ جمله به پرس‌وجو پاسخ مستقیم بدهد (برای featured snippet و پاسخ‌های AI)

**URL، canonical و زبان**
- [ ] slug لاتین کوتاه و kebab-case، الگوی `/blog/<slug>/` و هاب `/blog/`
- [ ] canonical خودارجاع روی هر صفحه
- [ ] `hreflang="fa-IR"` خودارجاع به‌علاوهٔ `x-default` روی هر مقاله، هم‌سو با صفحهٔ اصلی (نسخهٔ زبان دیگری فعلاً نداریم، پس جفت‌های متقابل لازم نیست)

**اسکیما (JSON-LD)**
- [ ] `BlogPosting` با `headline`، `datePublished`، `dateModified`، `author`، `publisher` (Organization) و `inLanguage: fa-IR`
- [ ] `BreadcrumbList` (خانه ← بلاگ ← مقاله)
- [ ] `FAQPage` از همان FAQ داخل صفحه. گوگل از ۲۰۲۳ نتیجهٔ غنی FAQ را تقریباً فقط برای سایت‌های دولتی و سلامت نشان می‌دهد، پس هدف معنایی است و برای پاسخ‌های AI، نه گرفتن rich result
- [ ] بدون `Product`، `Offer`، `Review` یا `AggregateRating` (طبق copy deck، چون قیمت و فروشی در کار نیست). بدون `HowTo` (منسوخ)

**لینک درونی**
- [ ] هر مقاله: لینک به ستون، حداقل ۲ مقالهٔ هم‌خوشه و ۱ بخش صفحهٔ اصلی، طبق جدول بالا
- [ ] breadcrumb قابل مشاهده، بلوک «مطالب مرتبط» و هاب `/blog/` با دسته‌بندی خوشه‌ای
- [ ] کلیدواژه‌های حذف‌شده در anchor، alt و تگ نیایند

**sitemap، robots و ایندکس**
- [ ] `vite.config.js` الان در sitemap فقط `/` را می‌نویسد: باید صفحه‌های بلاگ با `lastmod` واقعی هر مقاله به آن اضافه شوند و هر صفحه در `rollupOptions.input` ثبت شود (یا مقاله‌ها در زمان build از Markdown ساخته شوند)

- [ ] تأیید مالکیت در Google Search Console و Bing Webmaster، ارسال sitemap، و IndexNow برای Bing
- [ ] **دسترسی Googlebot به سرور ایران:** سایت روی VPS ایران است و Cloudflare فقط DNS را مدیریت می‌کند. چون اتصال بین‌المللی سرورهای داخلی گاهی ناپایدار است، با URL Inspection در Search Console و گزارش Crawl Stats مطمئن شوید که خزش بدون timeout انجام می‌شود. اگر خطا دیدید، CDN یا proxy جلوی سایت را بررسی کنید
