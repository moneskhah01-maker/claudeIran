Claude API چیست؟ به زبان ساده، رابط برنامه‌نویسی (API) شرکت Anthropic است که به نرم‌افزار شما اجازه می‌دهد مدل‌های زبانی Claude را مستقیم صدا بزند. متن، و در صورت نیاز تصویر یا PDF، را در قالب یک درخواست HTTP می‌فرستید و پاسخ مدل را به شکل JSON پس می‌گیرید. هستهٔ این رابط یک endpoint به نام Messages API است و هزینه‌اش بر اساس تعداد توکن‌های ورودی و خروجی حساب می‌شود.

این راهنما برای توسعه‌دهندهٔ بک‌اند، مدیر محصول و مدیر فنی تیم‌های کوچک است: از مفهوم و ساختار درخواست شروع می‌کنیم، اولین درخواست را با curl و Python و Node.js می‌فرستیم و به موضوعی می‌رسیم که در تیم‌ها زود جدی می‌شود: کلید، بودجه و خطاها.

> **نکته:** کلاود ایران سرویسی مستقل و در مرحلهٔ پیش‌عرضه است و هیچ وابستگی‌ای به Anthropic ندارد. مرجع نهایی همهٔ جزئیات فنی این مقاله [مستندات رسمی Claude](https://docs.claude.com) است.

## Claude API چیست؟ تعریف در یک نگاه

Anthropic خانواده‌ای از مدل‌های زبانی بزرگ به نام Claude می‌سازد که از دو راه در دسترس است: اپ‌هایی برای گفت‌وگوی انسان، و API برای نرم‌افزار. این مقاله دربارهٔ راه دوم است.

### تفاوت API با اپ Claude

اپ Claude (وب، دسکتاپ و موبایل) محصولی آماده است: رابط، حافظهٔ گفت‌وگو و تنظیمات را خود اپ مدیریت می‌کند. API یک قطعهٔ ساختمانی است: شما تصمیم می‌گیرید چه متنی به مدل برسد، پاسخ کجا نمایش داده شود، چه داده‌ای ذخیره شود و هر درخواست چقدر خروجی داشته باشد.

| | اپ Claude | Claude API |
|---|---|---|
| مخاطب | انسان | نرم‌افزار شما |
| رابط | صفحهٔ گفت‌وگو | درخواست HTTP و پاسخ JSON |
| حافظهٔ گفت‌وگو | خود اپ نگه می‌دارد | شما نگه می‌دارید و هر بار می‌فرستید |
| صورتحساب | اشتراک | بر اساس توکن مصرفی |
| کنترل | تنظیمات محدود کاربر | پرامپت، مدل، سقف خروجی و ابزارها دست شماست |

### چه کسانی به API نیاز دارند

- **توسعه‌دهنده‌ای که می‌خواهد قابلیتی هوشمند به محصول اضافه کند:** خلاصهٔ خودکار، پاسخ پیشنهادی به مشتری یا جست‌وجوی معنایی در اسناد.
- **مدیر محصولی که دنبال تجربه‌ای اختصاصی است:** رابط، لحن و قواعد کسب‌وکار باید مال خود محصول باشد، نه یک پنجرهٔ گفت‌وگوی عمومی.
- **مدیر فنی یا CTO که ابزار داخلی و اتوماسیون می‌خواهد:** دسته‌بندی تیکت، بازبینی کد یا استخراج داده از فرم‌ها.
- **تیم داده که حجم زیادی متن را یک‌جا پردازش می‌کند:** برچسب‌گذاری، ترجمه یا تحلیل بازخورد.

اگر فقط می‌خواهید خودتان با مدل گفت‌وگو کنید، اپ کافی است. API وقتی معنا پیدا می‌کند که مدل باید بخشی از یک سیستم باشد.

## Claude API چطور کار می‌کند

### چرخهٔ درخواست و پاسخ و stateless بودن

هر تعامل با Claude API یک رفت‌وبرگشت ساده است:

```text
 your app                          Claude API
 ────────                          ──────────
 build request  ──POST /v1/messages──▶  model generates
 (model, max_tokens,                   the reply
  system, messages)
                ◀──── JSON reply ─────  content + stop_reason + usage
 store history,
 show the answer,
 log the usage
```

1. اپلیکیشن شما درخواست را می‌سازد: کدام مدل، حداکثر چند توکن خروجی، دستورالعمل سیستمی و پیام‌ها.
2. درخواست با متد POST به `https://api.anthropic.com/v1/messages` فرستاده می‌شود. کلید API در هدر `x-api-key` (یا به‌صورت `Authorization: Bearer`) و نسخهٔ API در هدر `anthropic-version` می‌آید.
3. مدل پاسخ را تولید می‌کند.
4. پاسخ JSON برمی‌گردد: محتوای پاسخ (`content`)، دلیل توقف (`stop_reason`) و مصرف توکن (`usage`).

نکتهٔ کلیدی این است که API **stateless** (بی‌حالت) است: سرور گفت‌وگوی قبلی را به خاطر نمی‌سپارد. اگر می‌خواهید مدل پیام‌های قبلی را بداند، باید کل تاریخچه را در هر درخواست دوباره بفرستید. دو پیامد مهم دارد: کنترل حافظه و حریم داده کاملاً دست شماست، و هر چه گفت‌وگو بلندتر شود، ورودی هر درخواست و در نتیجه هزینه‌اش بیشتر می‌شود.

### Messages API: پارامترهای `model`، `max_tokens`، `system` و `messages`

چهار پارامتر اصلی هر درخواست این‌هاست:

| پارامتر | کارکرد |
|---|---|
| `model` | شناسهٔ مدلی که باید پاسخ بدهد |
| `max_tokens` | سقف توکن‌های خروجی این درخواست؛ اجباری است و جلوی پاسخ‌های بی‌انتها و هزینهٔ پیش‌بینی‌نشده را می‌گیرد |
| `system` | دستورالعمل سیستمی (system prompt): نقش، قواعد، لحن و مرزهای پاسخ |
| `messages` | آرایهٔ پیام‌های گفت‌وگو، هر کدام با `role` و `content` |

پارامترهای دیگری هم هست که بعداً به آن‌ها می‌رسیم: `stream` برای استریم، `tools` برای اتصال به ابزارها و `output_config` برای تنظیم میزان تلاش مدل یا قالب خروجی. بدنهٔ یک درخواست ساده این شکلی است:

```json
{
  "model": "claude-opus-5-5",
  "max_tokens": 1024,
  "system": "You are a support assistant. Answer in Persian, briefly and politely.",
  "messages": [
    {"role": "user", "content": "سفارش من کی ارسال می‌شود؟"}
  ]
}
```

و پاسخ، به شکل خلاصه (اعداد نمونه‌اند):

```json
{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "model": "claude-opus-5-5",
  "content": [
    {"type": "text", "text": "..."}
  ],
  "stop_reason": "end_turn",
  "usage": {"input_tokens": 58, "output_tokens": 112}
}
```

`content` آرایه‌ای از «بلوک»هاست، نه یک رشتهٔ ساده. در مدل‌های جدید ممکن است پیش از بلوک متن، بلوکی از نوع `thinking` (تفکر) هم بیاید، و وقتی مدل ابزاری را صدا می‌زند، بلوک `tool_use` می‌آید. پس همیشه بلوک‌ها را بر اساس `type` فیلتر کنید و فرض نکنید اولین بلوک متن است.

`stop_reason` می‌گوید چرا تولید متوقف شد: `end_turn` یعنی پاسخ کامل شده، `max_tokens` یعنی به سقف خورده و پاسخ ناتمام است، `tool_use` یعنی مدل منتظر نتیجهٔ یک ابزار است، و `refusal` یعنی مدل به دلایل ایمنی از پاسخ خودداری کرده است. این فیلد را همیشه پیش از استفاده از پاسخ بررسی کنید.

### نقش‌ها و نگه‌داشتن تاریخچهٔ گفت‌وگو

در `messages` دو نقش اصلی داریم: `user` برای ورودی کاربر یا اپلیکیشن، و `assistant` برای پاسخ‌های قبلی مدل. اولین پیام باید از نوع `user` باشد. دستورالعمل سیستمی جای جداگانه‌ای دارد (`system`) و داخل این آرایه نمی‌آید.

برای گفت‌وگوی چندنوبتی، بعد از هر پاسخ، آن را با نقش `assistant` به تاریخچه اضافه کنید و پیام بعدی کاربر را پشتش بگذارید:

```python
import anthropic

client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from the environment
history = []

def ask(text: str) -> str:
    history.append({"role": "user", "content": text})
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=1024,
        system="You are a helpful assistant. Reply in Persian.",
        messages=history,
    )
    # keep the full content blocks, not just the text
    history.append({"role": "assistant", "content": response.content})
    return "".join(b.text for b in response.content if b.type == "text")

print(ask("اسم من سارا است."))
print(ask("اسم من چه بود؟"))  # the model knows only because we resent the history
```

در محصول واقعی، تاریخچه را در پایگاه دادهٔ خودتان نگه می‌دارید و گفت‌وگوهای بلند را کوتاه یا خلاصه می‌کنید، وگرنه هزینهٔ هر نوبت مدام بالا می‌رود. جزئیاتش را در راهنمای [کنترل هزینهٔ API هوش مصنوعی](/blog/ai-api-cost-control/) آورده‌ایم.

## مدل‌ها، توکن و صورتحساب

### مدل‌های Claude در یک پاراگراف

Claude در چند رده عرضه می‌شود. **Haiku** سریع‌ترین و کم‌هزینه‌ترین رده است و برای کارهای پرحجم و ساده مثل دسته‌بندی و استخراج مناسب است. **Sonnet** تعادل کیفیت، سرعت و هزینه است و بسیاری از تیم‌ها کار روزمرهٔ تولیدی را با آن انجام می‌دهند. **Opus** ردهٔ توانمند این خانواده است برای استدلال سنگین، کدنویسی پیچیده و تحلیل اسناد بلند. هر مدل یک شناسهٔ دقیق دارد که در پارامتر `model` می‌نشیند، مدل‌ها با نسخه‌های تازه جایگزین می‌شوند و مدل‌های قدیمی به‌مرور بازنشسته می‌شوند. معیار انتخاب و الگوی ترکیب چند مدل را در [راهنمای انتخاب مدل Claude](/blog/claude-models-haiku-sonnet-opus/) توضیح داده‌ایم.

> **نکته:** مدل‌های فعلی طبق مستندات رسمی (آخرین بازبینی: ۲ آذر ۱۴۰۵): Opus با شناسهٔ `claude-opus-5-5`، Sonnet با `claude-sonnet-5-5` و Haiku با `claude-haiku-5-5`. نمونه‌کدهای این مقاله `claude-opus-5-5` را به کار می‌برند. این فهرست با هر انتشار مدل تغییر می‌کند؛ پیش از استفاده آن را در [مستندات رسمی](https://docs.claude.com) چک کنید.

برای دانستن قابلیت‌های یک مدل در زمان اجرا، لازم نیست به حافظه یا جدول‌های قدیمی تکیه کنید. Models API (`GET /v1/models`) برای هر مدل، اندازهٔ پنجرهٔ زمینه (`max_input_tokens`)، سقف خروجی (`max_tokens`) و قابلیت‌هایی مثل ورودی تصویر یا تفکر را برمی‌گرداند.

### توکن و پنجرهٔ زمینه

مدل متن را کلمه‌به‌کلمه نمی‌خواند، بلکه آن را به تکه‌هایی به نام **توکن (Token)** می‌شکند. هر توکن ممکن است یک کلمهٔ کامل، بخشی از کلمه یا یک علامت باشد. هم ورودی و هم خروجی با توکن اندازه‌گیری می‌شوند و فیلد `usage` در هر پاسخ دقیقاً می‌گوید چند توکن ورودی (`input_tokens`) و چند توکن خروجی (`output_tokens`) مصرف شده است.

**پنجرهٔ زمینه (context window)** سقف تعداد توکنی است که مدل در یک درخواست می‌تواند در نظر بگیرد: دستورالعمل سیستمی، کل تاریخچه، اسناد پیوست و پاسخی که تولید می‌کند. مدل‌های فعلی Claude پنجرهٔ زمینهٔ بزرگی دارند، اما عدد دقیقش به مدل بستگی دارد و باید آن را از مستندات یا Models API بخوانید. اگر ورودی از این سقف بیشتر شود، API خطای ۴۰۰ با پیام «prompt is too long» برمی‌گرداند.

### صورتحساب

هزینهٔ Claude API بر اساس توکن حساب می‌شود و توکن ورودی و توکن خروجی نرخ جداگانه دارند. نرخ خروجی معمولاً بیشتر از ورودی است و هر مدل نرخ خودش را دارد. ساده‌ترین شکل فرمول این است:

```text
cost = input_tokens × input_rate + output_tokens × output_rate
```

دو سازوکار این هزینه را پایین می‌آورند: کش پرامپت برای بخش‌های تکراری ورودی، و پردازش دسته‌ای (Batch) برای کارهای غیرفوری. نرخ‌های به‌روز فقط در [صفحهٔ رسمی قیمت‌گذاری Anthropic](https://www.anthropic.com/pricing) معتبرند. فرمول کامل، اثر کش و یک مثال عددی را در [محاسبهٔ هزینهٔ توکن در Claude API](/blog/claude-tokens-pricing/) ببینید.

## قابلیت‌های کلیدی Claude API

همهٔ قابلیت‌های زیر از همان endpoint پیام‌ها (`/v1/messages`) استفاده می‌کنند و API جداگانه‌ای نیستند. فقط Batch، شمارش توکن و بارگذاری فایل endpointهای کمکی خودشان را دارند.

### استریم پاسخ

با `"stream": true` پاسخ به‌جای یک‌جا، به شکل رویدادهای Server-Sent Events (SSE) و تکه‌تکه می‌رسد: `message_start`، سپس برای هر بلوک `content_block_start`، رویدادهای `content_block_delta` که متن را ذره‌ذره می‌آورند و `content_block_stop`، بعد `message_delta` با `stop_reason` و مصرف توکن خروجی، و در پایان `message_stop`. کاربر اولین کلمه‌ها را زود می‌بیند و درخواست‌های با خروجی طولانی به timeout نمی‌خورند:

```python
with client.messages.stream(
    model="claude-opus-5-5",
    max_tokens=4096,
    messages=[{"role": "user", "content": "یک ایمیل خوش‌آمدگویی کوتاه بنویس."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
    final = stream.get_final_message()

print("\noutput tokens:", final.usage.output_tokens)
```

### Tool use

Tool use (استفاده از ابزار، معادل function calling) راهی است که مدل از طریق آن با سیستم‌های شما کار می‌کند. شما در پارامتر `tools` فهرست ابزارها را با نام، توضیح و یک JSON Schema برای ورودی تعریف می‌کنید. اگر مدل تشخیص بدهد که برای پاسخ به یک ابزار نیاز دارد، پاسخش با `stop_reason: "tool_use"` و یک بلوک `tool_use` برمی‌گردد که نام ابزار و ورودی‌هایش را دارد.

اجرای ابزار کار کد شماست: مثلاً وضعیت سفارش را از پایگاه داده می‌خوانید و نتیجه را با بلوک `tool_result` در پیام بعدی می‌فرستید تا مدل پاسخ نهایی را بسازد:

```json
{
  "name": "get_order_status",
  "description": "Look up the shipping status of an order by its ID.",
  "input_schema": {
    "type": "object",
    "properties": {
      "order_id": {"type": "string", "description": "Order ID, e.g. A-1042"}
    },
    "required": ["order_id"]
  }
}
```

علاوه بر ابزارهای خودتان، ابزارهای سمت سرور هم هست که روی زیرساخت Anthropic اجرا می‌شوند، مثل جست‌وجوی وب و اجرای کد. این‌ها را فقط اعلام می‌کنید و نتیجه‌شان در همان پاسخ می‌آید.

### ورودی تصویر و PDF

`content` یک پیام می‌تواند آرایه‌ای از بلوک‌ها باشد: بلوک `image` برای تصویر (به شکل `base64` یا URL) و بلوک `document` برای PDF، در کنار بلوک `text` که دستور شما را دارد. این برای استخراج داده از فاکتور اسکن‌شده یا خواندن جدول‌های یک گزارش کاربرد دارد. برای فایلی که در چند درخواست لازم است، Files API اجازه می‌دهد یک بار آپلودش کنید و با شناسه‌اش به آن ارجاع بدهید.

### Prompt caching و Batch

**کش پرامپت (prompt caching)** برای وقتی است که بخش بزرگی از ورودی در درخواست‌های پیاپی ثابت می‌ماند، مثل دستورالعمل سیستمی طولانی، سند مرجع یا تعریف ابزارها. با `cache_control` مشخص می‌کنید تا کجای ورودی کش شود و درخواست‌های بعدی که دقیقاً با همان پیشوند شروع شوند، آن بخش را با نرخ بسیار کمتری می‌خوانند. عمر پیش‌فرض کش پنج دقیقه است و هر خواندن آن را تمدید می‌کند. تغییر حتی یک بایت در بخش کش‌شده، مثلاً گذاشتن ساعت در system prompt، کش را باطل می‌کند. فیلد `usage.cache_read_input_tokens` نشان می‌دهد کش واقعاً کار کرده یا نه.

**پردازش دسته‌ای (Message Batches)** برای کارهایی است که کسی منتظر پاسخ فوری‌شان نیست، مثل پردازش شبانهٔ هزاران تیکت یا اجرای ارزیابی. درخواست‌ها را یک‌جا به `/v1/messages/batches` می‌فرستید، نتیجه‌ها ناهمگام و با هزینهٔ کمتر از درخواست عادی آماده می‌شوند و چون ترتیبشان تضمینی ندارد، هر کدام را با `custom_id` خودش شناسایی می‌کنید. شیوهٔ ترکیب این دو اهرم را در [کنترل هزینهٔ API هوش مصنوعی](/blog/ai-api-cost-control/) توضیح داده‌ایم.

### سازگاری با قالب OpenAI و محدودیت‌هایش

Anthropic یک لایهٔ سازگار با قالب OpenAI هم ارائه می‌کند (endpoint `/v1/chat/completions`) تا بتوانید کد موجود را با کمترین تغییر روی Claude امتحان کنید. این مسیر برای آزمایش و مقایسهٔ سریع خوب است، اما همهٔ قابلیت‌های Claude از آن در دسترس نیست. برای محصول تولیدی، Messages API بومی انتخاب مطمئن‌تری است. فهرست دقیق تفاوت‌ها در مستندات رسمی آمده و چک‌لیست عملی‌اش را در [مهاجرت از OpenAI به Claude](/blog/openai-to-claude-migration/) نوشته‌ایم. اگر هم بین دو ارائه‌دهنده مردد هستید، [مقایسهٔ Claude و ChatGPT برای تیم‌های فنی](/blog/claude-vs-chatgpt/) را بخوانید.

## اولین درخواست: curl، Python و Node.js

پیش‌نیازها کوتاه است:

1. حساب کاربری در کنسول Anthropic و تنظیم صورتحساب آن.
2. ساختن یک کلید API در کنسول.
3. گذاشتن کلید در متغیر محیطی، نه داخل کد:

```bash
export ANTHROPIC_API_KEY="..."   # never commit this value
```

**با curl:**

```bash
curl https://api.anthropic.com/v1/messages \
  -H "Content-Type: application/json" \
  -H "x-api-key: $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2026-10-21" \
  -d '{
    "model": "claude-opus-5-5",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "سه ایدهٔ کوتاه برای نام یک کافه بده."}
    ]
  }' | jq '{text: [.content[] | select(.type == "text") | .text], usage: .usage}'
```

**با Python** (نصب: `pip install anthropic`):

```python
import anthropic

client = anthropic.Anthropic()  # uses ANTHROPIC_API_KEY

response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "سه ایدهٔ کوتاه برای نام یک کافه بده."}],
)

if response.stop_reason == "refusal":
    print("Request was declined.")
else:
    for block in response.content:
        if block.type == "text":
            print(block.text)

print("input tokens:", response.usage.input_tokens)
print("output tokens:", response.usage.output_tokens)
```

**با Node.js** (نصب: `npm install @anthropic-ai/sdk`):

```javascript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic(); // uses ANTHROPIC_API_KEY

const response = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "سه ایدهٔ کوتاه برای نام یک کافه بده." }],
});

for (const block of response.content) {
  if (block.type === "text") console.log(block.text);
}
console.log("usage:", response.usage.input_tokens, response.usage.output_tokens);
```

> **نکته:** SDKهای رسمی هدرهای احراز هویت و `anthropic-version` را خودشان می‌فرستند و خطاهای موقت مثل ۴۲۹ و خطاهای سمت سرور را به‌طور پیش‌فرض دو بار و با فاصلهٔ فزاینده دوباره امتحان می‌کنند. اگر با HTTP خام کار می‌کنید، این منطق را خودتان بنویسید. نسخهٔ `2026-10-21` در نمونهٔ curl جدیدترین نسخهٔ API در زمان نگارش است و در آن پارامترهای `temperature`، `top_p` و `top_k` دیگر پذیرفته نمی‌شوند؛ نسخهٔ روز را از مستندات رسمی چک کنید.

پیش از ارسال یک ورودی بزرگ، می‌توانید با endpoint شمارش توکن (`/v1/messages/count_tokens`) بفهمید چند توکن ورودی مصرف می‌کند. این کار در Python با `client.messages.count_tokens(...)` انجام می‌شود، شمارش به توکنایزر هر مدل وابسته است و روش کاملش در مقالهٔ توکن آمده است.

## Claude API در تیم: کاربردها، کلید و بودجه

### کاربردهای رایج برای تیم‌ها

| کاربرد | الگوی فنی | نکتهٔ کلیدی |
|---|---|---|
| پاسخ‌گویی به مشتری | system prompt با قواعد و لحن برند، tool use برای وضعیت سفارش و اطلاعات حساب | برای موارد حساس، مسیر ارجاع به انسان بگذارید |
| خلاصه‌سازی اسناد و جلسات | ورودی بلند و دستور قالب خروجی مشخص، مثلاً «سه بند تصمیم و فهرست اقدام‌ها» | سند مرجع ثابت را کش کنید |
| دستیار کد و بازبینی | ارسال diff یا فایل‌ها همراه با معیارهای بازبینی تیم | خروجی را پیشنهاد بدانید، نه حکم نهایی |
| استخراج داده از فاکتور و فرم | ورودی تصویر یا PDF و خروجی JSON ساختاریافته | خروجی را پیش از ذخیره اعتبارسنجی کنید |
| دسته‌بندی تیکت و بازخورد | مدل سبک با `max_tokens` کم و فهرست برچسب‌های ثابت | برای حجم بالا و غیرفوری از Batch استفاده کنید |

در همهٔ این کاربردها، کیفیت خروجی بیش از هر چیز به پرامپت بستگی دارد: نقش روشن، داده‌ای که با تگ از دستور جدا شده و قالب خروجی مشخص. اصول عملی و نمونه‌های قبل و بعدش را در [پرامپت‌نویسی برای Claude](/blog/claude-prompt-engineering/) آورده‌ایم.

### دسترسی در تیم: کلید جدا برای هر پروژه، بودجه و سقف خروجی

بیشتر تیم‌ها با یک کلید مشترک شروع می‌کنند و بعد با سه مشکل روبه‌رو می‌شوند: معلوم نیست کدام پروژه چقدر خرج کرده، لو رفتن کلید همهٔ سرویس‌ها را قطع می‌کند، و هیچ سقفی جلوی یک حلقهٔ معیوب را نمی‌گیرد. چند قاعدهٔ ساده از ابتدا جلوی این‌ها را می‌گیرد:

- **کلید جدا برای هر پروژه و هر محیط** (توسعه، آزمایش و تولید)، تا مصرف قابل تفکیک باشد و ابطال یک کلید بقیه را از کار نیندازد.
- **کلید هرگز در مرورگر یا اپ موبایل نباشد.** درخواست‌ها همیشه از بک‌اند شما بروند و کلید در متغیر محیطی یا secret manager بماند.
- **سقف خروجی در کد:** مقدار `max_tokens` را متناسب با کار بگذارید، نه بزرگ‌ترین عدد ممکن.
- **بودجهٔ ماهانه و هشدار** برای هر پروژه، و بازبینی منظم گزارش مصرف.
- **محدود کردن مدل‌های مجاز** برای هر کلید، تا یک پروژهٔ ساده بی‌دلیل روی گران‌ترین مدل نرود.
- **لاگ بدون کلید:** کلید و دادهٔ حساس کاربر نباید در لاگ‌ها و پیام‌های خطا بیاید.

روش نگهداری، چرخش و واکنش به نشت کلید را در [امنیت کلید API در تیم](/blog/api-key-security/) و روش تعیین بودجه را در [کنترل هزینهٔ API هوش مصنوعی](/blog/ai-api-cost-control/) با جزئیات نوشته‌ایم. کلاود ایران، که هنوز در مرحلهٔ پیش‌عرضه است، این کنترل‌ها، یعنی کلید پروژه‌محور، بودجه، سقف خروجی و گزارش مصرف، را در [کنسول نمایشی](/console.html) خود طراحی کرده است؛ شرح [قابلیت‌ها](/#features) و [روش کار](/#how) در صفحهٔ اصلی آمده است.

## خطاهای رایج Claude API: ۴۰۰، ۴۰۱، ۴۲۹ و ۵۲۹

| کد | نوع خطا | معنی | چه کنیم | تکرار درخواست؟ |
|---|---|---|---|---|
| ۴۰۰ | `invalid_request_error` | قالب یا پارامترهای درخواست نادرست است، یا ورودی از پنجرهٔ زمینه بزرگ‌تر است | پیام خطا را بخوانید؛ معمولاً پارامتر جاافتاده، نقش نادرست یا ورودی بیش از حد بلند است | خیر، اول درخواست را اصلاح کنید |
| ۴۰۱ | `authentication_error` | کلید API نامعتبر است یا ارسال نشده | متغیر محیطی و هدر `x-api-key` را بررسی کنید؛ اگر کلید باطل شده، کلید تازه بسازید | خیر |
| ۴۲۹ | `rate_limit_error` | از سقف تعداد درخواست یا توکن در دقیقه عبور کرده‌اید، یا سازمان به سقف ماهانهٔ خرج رسیده است | طبق هدر `retry-after` صبر کنید و با فاصلهٔ فزاینده دوباره بفرستید؛ ۴۲۹ سقف خرج هدر `retry-after` ندارد و تکرارش فایده‌ای ندارد | بله، مگر سقف خرج |
| ۵۲۹ | `overloaded_error` | سرویس موقتاً زیر بار سنگین است | با فاصلهٔ فزاینده دوباره امتحان کنید و برای کاربر پیام مناسب نشان دهید | بله |

دو خطای دیگر هم گاهی دیده می‌شوند: ۴۱۳ (`request_too_large`) وقتی حجم خود درخواست از حد مجاز بیشتر است، و خطاهای ۵۰۰ سمت سرور که باید مثل ۵۲۹ با تأخیر دوباره امتحان شوند. در کد، خطاها را از خاص به عام بگیرید تا خطاهای قابل تکرار از خطاهای ناشی از درخواست نادرست جدا بمانند:

```python
import anthropic

try:
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=1024,
        messages=[{"role": "user", "content": "سلام"}],
    )
except anthropic.BadRequestError as e:         # 400: fix the request, do not retry
    print("bad request:", e.message)
except anthropic.AuthenticationError:          # 401: check the key
    print("invalid or missing API key")
except anthropic.RateLimitError as e:          # 429: back off
    print("rate limited, retry after:", e.response.headers.get("retry-after"))
except anthropic.APIStatusError as e:          # 5xx and 529: retry later
    print("server error:", e.status_code)
except anthropic.APIConnectionError:
    print("network error")
```

شناسهٔ هر درخواست (`request-id` در هدر پاسخ) را هم لاگ کنید. وقتی بخواهید مشکلی را پیگیری کنید، این شناسه کار را بسیار ساده می‌کند.

## جمع‌بندی و قدم بعدی

> **خلاصه:** Claude API یک endpoint اصلی دارد (`/v1/messages`) و بی‌حالت است، پس تاریخچه را خودتان می‌فرستید. هزینه با توکن ورودی و خروجی جداگانه حساب می‌شود. استریم، tool use، ورودی تصویر و PDF، کش و Batch همه روی همین پایه سوارند. در تیم، کلید جدا برای هر پروژه، سقف خروجی و بودجه را از روز اول جدی بگیرید.

اگر تازه شروع کرده‌اید، این مسیر مطالعه را پیشنهاد می‌کنیم: اول [توکن و محاسبهٔ هزینه](/blog/claude-tokens-pricing/)، بعد [انتخاب بین Haiku، Sonnet و Opus](/blog/claude-models-haiku-sonnet-opus/)، و پیش از رفتن به محیط تولید، [امنیت کلید API](/blog/api-key-security/). نمونه‌های بیشتر برای توسعه‌دهندگان را در [بخش توسعه‌دهندگان](/#developers) گذاشته‌ایم. اگر می‌خواهید هنگام آماده شدن سرویس خبردار شوید، می‌توانید در [فهرست دسترسی زودهنگام](/#early-access) عضو شوید؛ راه‌اندازی سرویس به قطعی شدن تأمین مورد تأیید و قرارداد بستگی دارد.

## سؤالات متداول

### Claude API با اشتراک claude.ai چه فرقی دارد؟
اشتراک claude.ai برای گفت‌وگوی انسان با Claude در اپ وب، دسکتاپ یا موبایل است و هزینه‌اش ثابت و دوره‌ای است. Claude API برای نرم‌افزار است: برنامهٔ شما درخواست می‌فرستد و هزینه بر اساس توکن مصرفی حساب می‌شود. این دو صورتحساب جداگانه دارند و اشتراک اپ، اعتبار API به حساب نمی‌آید.

### برای شروع کار با Claude API چه چیزهایی لازم است؟
یک حساب در کنسول Anthropic با صورتحساب فعال، یک کلید API و یکی از SDKهای رسمی مثل `anthropic` برای Python یا `@anthropic-ai/sdk` برای Node.js. کلید را در متغیر محیطی نگه دارید و اولین درخواست را با یک پیام کوتاه و `max_tokens` کم بفرستید تا ساختار پاسخ و فیلد `usage` را ببینید.

### Claude API متن فارسی را می‌فهمد و فارسی پاسخ می‌دهد؟
بله، Claude چندزبانه است و می‌تواند متن فارسی را بخواند و به فارسی پاسخ بدهد. برای نتیجهٔ یکدست، در system prompt زبان، لحن و قواعد نگارشی مثل نیم‌فاصله را صریح بنویسید. کیفیت را هم روی نمونه‌های واقعی کار خودتان بسنجید، چون اصطلاحات تخصصی هر حوزه فرق می‌کند.

### هزینهٔ Claude API چطور محاسبه می‌شود؟
هزینهٔ هر درخواست از جمع دو بخش به دست می‌آید: تعداد توکن‌های ورودی ضرب در نرخ ورودی، و تعداد توکن‌های خروجی ضرب در نرخ خروجی. نرخ خروجی معمولاً بالاتر است و هر مدل نرخ خودش را دارد. کش پرامپت و پردازش Batch می‌توانند هزینه را کم کنند و نرخ‌های به‌روز فقط در صفحهٔ رسمی قیمت‌گذاری Anthropic معتبرند.

### می‌شود کدی که برای OpenAI نوشته شده را به Claude وصل کرد؟
بله، Anthropic یک لایهٔ سازگار با قالب OpenAI دارد که برای آزمایش سریع کد موجود مناسب است. اما همهٔ قابلیت‌های Claude از این مسیر در دسترس نیست. برای محصول تولیدی بهتر است کد را به Messages API بومی منتقل کنید و پرامپت‌ها را هم دوباره بازبینی کنید.
